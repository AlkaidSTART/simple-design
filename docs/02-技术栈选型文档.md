# 技术栈选型文档

> 版本：v1.0（归一化基线）｜ 日期：2026-08-06
> 来源：全栈架构设计 v0.1 + DevOps 成本 v1.0 + QA 策略 v1.0 归一化
> 原则：**框架无关核心 + 轻依赖 + 客户端导出优先 + 托管服务免运维**

---

## 1. 选型总览

| 层级 | 选型 | 版本/说明 | 替代方案 | 决策理由 |
|---|---|---|---|---|
| 前端框架 | **React 19 + TypeScript** | Vite 6 构建 | Vue 3 / Svelte 5 | 画布工具生态最成熟（react-use-gesture / dnd-kit / framer-motion）；核心逻辑抽 `packages/core` 框架无关，可迁移 |
| 状态管理 | **Zustand** | — | Redux Toolkit / Jotai | selector 订阅避免全树重渲染；画布高频更新场景下比 Redux 轻 |
| 样式 | **Tailwind CSS v4** | `@tailwindcss/vite` 插件，CSS-first 配置 | CSS Modules / styled-components | 编辑器 UI 与导出 HTML 同源（CDN / v4 构建双路线）；`@theme` 定义毛玻璃语义变量 |
| 数据校验 | **Zod** | — | Yup / Valibot | 前后端共享 schema，TS 类型推导零成本 |
| 画布核心 | **自研 viewport 引擎 + Pointer Events** | 不引入重依赖 | react-flow / tldraw / react-rnd | 可控、无锁定；200 图层内线性扫描 + AABB 预过滤足够；千级图层换 rbush |
| 本地持久化 | **IndexedDB（idb-keyval）** | — | localStorage（容量/性能不足） | 自动保存草稿、离线友好 |
| 云端存储（v0.2+） | **Postgres(JSONB) + Cloudflare R2** | Supabase / Neon | 传统云厂商对象存储 | 文档与图片资源分离；R2 零出口费 |
| 导出 | **html2canvas-pro + JSZip** | html2canvas-pro（社区 fork，性能更好） | 自渲染 canvas / Puppeteer | 客户端零成本；预留 IRenderer 接口，v1.0 可换自渲染 |
| 部署 | **Vercel（静态 → Serverless）** | Hobby 起步 $0 | Cloudflare Pages / Netlify | 免费带宽 100GB/月、Instant Rollback、PR 预览 |
| 认证 | Supabase Auth / Better Auth | v0.2+ | — | 托管、免运维 |
| 测试 | **Vitest + Playwright + pixelmatch** | — | Jest + Cypress | 与 Vite 同栈；移动端手势模拟强；像素断言基线库 |
| CI/CD | **GitHub Actions** | shard 分片 | — | 免费、与 GitHub 一体 |

**刻意不引入**：redux、react-flow、tldraw、react-rnd、K8s、自研渲染引擎（MVP 期）。

## 2. 前端选型论证

### 2.1 为什么 React 19 + Vite 6
- 画布编辑器 = 「高频指针事件 + 局部 DOM 更新 + 复杂拖拽」，React 生态的 `react-use-gesture`、`dnd-kit`、`framer-motion` 可直接复用
- Vite 6 开发体验（HMR 毫秒级）+ 构建产物小（tree-shaking）
- 备选 Vue3 / Svelte5 均可，因核心逻辑在 `packages/core`（框架无关），迁移成本可控

### 2.2 为什么 Zustand
- 画布状态（viewport、elements、selection）高频变更，Zustand 的 selector 订阅机制让未订阅组件零重渲染
- 无 Provider 嵌套、样板代码少，适合单页工具型应用

### 2.3 为什么 Tailwind v4
- **关键收益：编辑器与导出同源**——导出 HTML 的样式生成器（`stylesFromLayer`）与画布渲染共用，保证「所见即所得」
- 导出双路线：
  - **路线 A（原型期）**：CDN `<script src="https://cdn.tailwindcss.com">`，导出单文件即开即用
  - **路线 B（正式版）**：`@tailwindcss/cli` 生成最小化 CSS 内联，规避 CDN 依赖
- 约束：导出里只用静态 class 或 CSS 变量，绕开 CDN JIT 限制

### 2.4 性能原则
1. 图层移动/缩放用 `transform` 而非改 top/left（只走 composite 层）
2. 视口裁剪（viewport culling），画布外元素不渲染
3. 画布状态与 UI 状态分离
4. **导出用克隆 DOM，绝不对交互中的屏幕 DOM 截图**

## 3. 画布引擎选型

### 3.1 自研 vs 现成库

| 维度 | 自研 viewport 引擎 | react-flow / tldraw |
|---|---|---|
| 控制力 | 完全可控 | 受框架约束 |
| 依赖体积 | 零额外依赖 | 大 |
| 学习成本 | 中（几何变换核心 ~200 行） | 低 |
| 灵活性 | 高（可随时换导出策略） | 低（导出/自定义层受限） |
| 风险 | 坐标系 bug（QA 已覆盖 P0） | 升级锁死 |

**决策**：自研。核心几何（viewport transform / zoomAt / hit-test）抽为纯函数，单测密度高（≥85% 覆盖率），QA 第一周即可锁住正确性。

### 3.2 关键几何约定
- Viewport Transform（origin 恒为 0,0，避免漂移）：`屏幕坐标 = 世界坐标 × scale + pan`
- DOM：viewport 层 `touch-action:none`；world 层 `transform: translate(x,y) scale(s)`（translate→scale 顺序）
- 缩放边界：0.1x – 4x，以鼠标/捏合中心为锚点
- 命中测试：世界坐标下逆序线性扫描 + AABB 预过滤（<200 图层）；旋转图层先逆旋转再判 OBB；v1.0 千级图层换 rbush
- 拖拽：Pointer Events 统一处理 + `setPointerCapture`

## 4. 数据层选型

### 4.1 校验：Zod（前后端共享）
- `packages/core` 定义 `Document / Artboard / Layer`（discriminatedUnion），前后端同一 schema
- strict/lenient 双模式：内部解析 lenient（容错），写入前 strict（保证一致性）

### 4.2 本地持久化：IndexedDB（idb-keyval）
- 变更 debounce 800ms + beforeunload flush
- 图片 v0.1 用 `FileReader → dataURL`（本地零服务端、导出 ZIP 自包含）；objectURL 预览防文档膨胀

### 4.3 云端（v0.2+）
| 项 | 选型 | 说明 |
|---|---|---|
| 数据库 | Postgres JSONB（Supabase/Neon） | document 整存 JSONB + 版本号乐观并发 |
| 对象存储 | Cloudflare R2 | **零出口费刚需**（设计师 SaaS 带宽是最大成本驱动） |
| 认证 | Supabase Auth | 托管免运维 |

乐观并发：`UPDATE ... SET content, version+1 WHERE id AND version`（0 行影响 = 409）。

## 5. 导出管线选型

```
[Document] → 序列化 → 离屏克隆 DOM → 分发
              ├─ PNG:  html2canvas-pro → dataURL → 下载（scale=2, useCORS, fonts.ready）
              ├─ HTML: 独立单文件（Tailwind CDN + 内联资源）
              └─ ZIP:  JSZip 打包 index.html + assets/ + previews/ + manifest.json
```

### 5.1 为什么 html2canvas-pro
- 社区 fork 版：修复原版 oklch 颜色支持问题、性能更优
- 与 jsPDF 路线相比，对「视觉保真」场景更直接
- 颜色统一转 hex/rgb（规避 oklch 兼容问题）

### 5.2 风险与演进
- html2canvas 保真度是已知瓶颈 → **预留 `IRenderer` 接口**，v1.0 换自渲染 canvas 无缝切换
- **最关键的 DRY 约束**：画布渲染与导出的图层样式生成器必须是同一函数 `stylesFromLayer`（否则「编辑器好看、导出一团糟」）——代码评审强制点

## 6. 部署与成本选型

### 6.1 分阶段方案

| 阶段 | 方案 | 月成本 |
|---|---|---|
| v0.1 静态验证 | Vercel Hobby 静态 + 客户端导出，**零后端** | $0 |
| MVP（0–500 MAU） | Vercel + Supabase(DB+Auth) + R2 | ≈$1–26 |
| 增长期（5K–20K MAU） | Vercel Pro + Supabase Medium + R2 + Queues | ≈$175–395 |

### 6.2 成本关键决策
1. **导出永远客户端优先**——服务端只做「ZIP 元数据 + 签名上传 URL」轻活（若误做成服务端渲染，成本翻 2–4 倍到 $600+）
2. **对象存储零出口费是刚需**（R2），砍掉传统云最贵的一项
3. 数据库用托管 Postgres（Supabase/Neon），**5 万 MAU 前不碰 K8s**
4. 自动保存必须**防抖 + 无变化检测**，否则烧 Serverless 调用量
5. Supabase Spend Cap 预算红线 + 每月 FinOps 巡检（带宽/存储/函数三张报表）

## 7. 工程质量选型

### 7.1 测试金字塔

```
        E2E (拖拽/缩放/导出回环)      ~15%  最高业务价值
        集成 (导出管线/数据流)        ~25%
        单元 (几何/坐标/校验)         ~50%  ← 核心成本与覆盖率来源
        静态/类型/快照               ~10%
```

| 层级 | 工具 | 重点 |
|---|---|---|
| 单测/集成 | Vitest | zoomAt / hit-test / schema / stylesFromLayer；几何校验模块覆盖率 ≥85% |
| E2E | @playwright/test | 手势语义化断言（相对偏移）、移动端模拟、tracing 排障 |
| 像素比对 | pixelmatch + 基线图库 | PNG diff < 0.5%（抗锯齿/字体基线容差） |
| CI | GitHub Actions + shard 分片 | lint + typecheck + 单测 + Playwright 冒烟；P0 回归阻断合并 |

### 7.2 兼容性选型
- 浏览器矩阵：Chromium（最新+上一版）、Safari、Firefox ESR（功能级）
- 触控断言：`touch-action:none`（pinch 不触发页面缩放）
- dpr 1/2/3 渲染与导出分辨率
- **毛玻璃降级 feature flag**（低端 pad/鸿蒙/部分 Android WebView 对 backdrop-filter 支持残缺）

## 9. 选型决策记录（ADR 摘要）

| ADR | 决策 | 被否方案 | 理由 |
|---|---|---|---|
| ADR-001 | 自研画布引擎 | tldraw / react-flow | 控制力 + 轻依赖 + 核心纯函数可测 |
| ADR-002 | 客户端导出 | 服务端渲染导出 | 成本第一杠杆（服务端导出成本 ×2–4） |
| ADR-003 | R2 对象存储 | AWS S3（出口费高） | 设计师 SaaS 带宽刚需，零出口费 |
| ADR-004 | html2canvas-pro + IRenderer 抽象 | 直接锁 html2canvas | 保真度瓶颈可替换 |
| ADR-005 | Zustand | Redux Toolkit | 高频画布更新的重渲染控制 |
| ADR-006 | 托管 Postgres | 自建 DB / K8s | 免运维，5 万 MAU 前不进 K8s 话题 |
| ADR-007 | 双主题（晨昏）+ 毛玻璃降级开关 | 全局毛玻璃主题 | 低端机性能与 WCAG 对比度风险 |
