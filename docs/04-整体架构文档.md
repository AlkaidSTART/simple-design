### 1.2 架构原则

| 原则 | 说明 |
|---|---|
| **客户端优先** | 导出、自动保存、渲染全部客户端完成，服务端只做轻活 → 成本第一杠杆 |
| **框架无关核心** | `packages/core` 纯 TS 无 React 依赖，可测试、可迁移、可复用 |
| **渐进增强** | 毛玻璃/云同步/协作均为可降级层，基础功能不依赖增强层 |
| **托管服务** | 不碰 K8s、不自建基础设施，5 万 MAU 前全部托管 |
| **同源渲染** | 画布与导出共用 `stylesFromLayer`，杜绝「所见≠所得」 |
| **可演进** | IRenderer 抽象、Yjs 接入点、rbush 引入点均为预留演进位 |

## 3. 核心子系统设计

### 3.1 画布引擎（自研 viewport）

**Viewport Transform**（origin 恒为 0,0，避免漂移）：
```
屏幕坐标 = 世界坐标 × scale + pan
```
DOM：viewport 层 `touch-action:none`；world 层 `transform: translate(x,y) scale(s)`（translate→scale 顺序）。

**以鼠标为中心缩放**：
```ts
function zoomAt(cursor, factor, vp) {
  const newScale = clamp(vp.scale * factor, 0.1, 4);
  const w = screenToWorld(cursor, vp);
  return { scale: newScale, x: cursor.x - w.x * newScale, y: cursor.y - w.y * newScale };
}
```
- Ctrl/Cmd+滚轮缩放（factor=exp(-deltaY*0.01)）；普通滚轮/双指平移
- 双指捏合：锚点=两指中点，`scale = clamp(startDist 比值, 0.1, 4)`

**拖拽**：Pointer Events 统一处理 + `setPointerCapture`。空白拖=平移画布；元素拖=移动元素；中键/空格+拖=平移。

**命中测试**：世界坐标逆序线性扫描 + AABB 预过滤（<200 图层）；旋转图层先逆旋转再判 OBB；v1.0 千级图层换 rbush。

**性能原则**：
1. 图层移动用 `transform` 只走 composite
2. 视口裁剪（culling）
3. 画布状态与 UI 状态分离（Zustand selector）
4. 导出用**克隆 DOM**，绝不对交互中的屏幕 DOM 截图

### 3.2 数据模型（Zod，前后端共享）

```ts
const LayerBase = z.object({
  id: z.string().uuid(), type: z.enum(['rect','text','image','group']),
  name: z.string().default('图层'),
  x: z.number(), y: z.number(), width: z.number().min(0), height: z.number().min(0),
  rotation: z.number().default(0), opacity: z.number().min(0).max(1).default(1),
  visible: z.boolean().default(true), locked: z.boolean().default(false),
  parentId: z.string().uuid().nullable(), zIndex: z.number().default(0),
});
// RectLayer: + fill/stroke/strokeWidth/radius
// TextLayer: + text/fontSize/fontFamily/fontWeight/color/align/lineHeight
// ImageLayer: + src(dataURL 或 URL)/objectFit
// GroupLayer: + children 递归
const Layer = z.discriminatedUnion('type', [RectLayer, TextLayer, ImageLayer, GroupLayer]);

const Artboard = z.object({ id, name, width, height, background, x, y, layers: z.array(Layer) });
const Document = z.object({ id, name, artboards, viewport(会话级，不入版本), createdAt, updatedAt, version });
```

原则：纯数据、可序列化、可版本化；世界坐标+像素单位；扁平数组+parentId；strict/lenient 双模式。

### 3.3 持久化

| 阶段 | 存储 | 触发 |
|---|---|---|
| v0.1 | IndexedDB（idb-keyval） | 变更 debounce 800ms + beforeunload flush |
| v0.2+ | Postgres JSONB + R2 | 保存 + 离开页面 flush |
| v1.0 | document_versions 快照表 | 每次保存 |

图片：v0.1 `FileReader → dataURL`（自包含、零服务端）；v0.2 上传 R2、导出时 assets 打包。
乐观并发：`UPDATE ... SET content, version+1 WHERE id AND version`（0 行影响 = 409）。
保存节流：**防抖 + 无变化检测**（hash diff），避免烧 Serverless 调用量。

### 3.4 导出管线

```
[Document] → 序列化 → 离屏克隆 DOM → 分发
              ├─ PNG:  html2canvas-pro → dataURL → 下载（scale=2, useCORS, fonts.ready）
              ├─ HTML: 独立单文件（Tailwind CDN 内联 + 资源内联）
              └─ ZIP:  JSZip 打包 index.html + assets/ + previews/ + manifest.json
```

- PNG：`await document.fonts.ready` 防文字偏移；颜色统一 hex/rgb（规避 oklch 兼容问题）
- HTML：**画布与导出样式生成器必须同一 `stylesFromLayer`**（最关键的 DRY 约束，代码评审强制点）
- v0.1 不做：渐变/混合模式完美保真、交互式 HTML
- 演进：`IRenderer` 接口隔离，v1.0 换自渲染 canvas（服务端高保真导出）

### 3.5 导出 HTML 双路线

| 路线 | 场景 | 说明 |
|---|---|---|
| A（原型期） | 导出单文件 | Tailwind CDN `<script>`，即开即用 |
| B（正式版） | 导出单文件 | `@tailwindcss/cli` 最小化 CSS 内联，无 CDN 依赖 |

约束：导出只用静态 class 或 CSS 变量，绕开 CDN JIT 限制。

## 4. 基础设施与部署

### 4.1 分阶段部署

| 阶段 | 方案 | 月成本 | 说明 |
|---|---|---|---|
| v0.1 静态验证 | Vercel Hobby + 纯静态 + 客户端导出 | **$0** | 零后端，验证需求 |
| MVP（0–500 MAU） | Vercel + Supabase(DB+Auth) + R2 | ≈$1–26 | 上账号与云保存 |
| 增长期（5K–20K MAU） | Vercel Pro + Supabase Medium + R2 + Queues + Sentry T2 | ≈$175–395 | 导出异步化、CDN、冷热分层 |
| 规模期 | Neon autoscale / Supabase 分页 + FinOps 巡检制度化 | 视规模 | 5 万 MAU 前不进 K8s |

### 4.2 关键成本决策
1. **导出永远客户端优先**——服务端只做「ZIP 元数据 + 签名上传 URL」（若服务端渲染导出，成本翻 2–4 倍）
2. **R2 零出口费**（对象存储是设计师 SaaS 最大成本驱动之一）
3. 自动保存防抖 + 无变化检测
4. Supabase Spend Cap 预算红线；P2 冷热分层（旧版本 → R2 IA $0.01/GB）；Neon scale-to-zero
5. 每月 FinOps 巡检：带宽 / 存储 / 函数三张报表

### 4.3 CI/CD
- **主干分支 + PR 预览**：feature/* → Vercel Preview URL，设计师直接点开体验
- **质量门禁**：lint + typecheck + 单测 + Playwright 冒烟（画布交互、导出关键路径）
- **小步快跑**：1 天数次小发版；Vercel Instant Rollback 一键回滚
- **DB 迁移**：up/down 脚本、先备份再迁移、破坏性变更双步走
- **功能开关**：编辑器重交互用 Feature Flag（Vercel Flags）灰度（含毛玻璃降级开关）

### 4.4 可观测 / 安全 / 备份

| 需求 | 工具 | 起步 |
|---|---|---|
| 前端错误 | Sentry（v0.1 必装） | Free |
| 运行时日志 | Vercel Logs → Logflare/Axiom | $0 |
| 分析 | Vercel Analytics / GA4 | Free |
| DB 指标 | Supabase Metrics / Neon | Free |

安全：CSP/安全头 + `X-Frame-Options`（防 iframe 套壳）、速率限制、密钥管理（Doppler/Vercel）。
备份：托管 Postgres 自动备份 + PITR + 每日导出 R2 冷存。

## 5. 数据流

### 5.1 编辑数据流（v0.1 纯本地）
```
用户操作 → Pointer Events → core/viewport 几何计算 → Zustand store 更新
  → stylesFromLayer → 画布 DOM（transform 驱动，composite only）
  → debounce 800ms → IndexedDB 持久化（version 递增）
```

### 5.2 导出数据流
```
Document → core/exporter 序列化 → 离屏克隆 DOM（无选中态）
  → PNG: html2canvas-pro(clone, {scale:2}) → Blob → 下载
  → HTML: stylesFromLayer 生成内联样式 → 单文件 → 下载
  → ZIP: JSZip(index.html + preview.png + manifest.json) → Blob → 下载
```

### 5.3 云同步数据流（v0.2+）
```
本地编辑 → 防抖保存 → POST /documents（签名上传 URL 由服务端签发）
  → 图片→R2、文档→Postgres JSONB（version 乐观并发，409 冲突提示）
  → 加载：GET /documents/:id（含 assets 引用列表）
```

## 6. 测试架构（QA 策略落地）

### 6.1 测试金字塔

```
        E2E (拖拽/缩放/导出回环)      ~15%  Playwright
        集成 (导出管线/数据流)        ~25%  Vitest + pixelmatch
        单元 (几何/坐标/校验)         ~50%  Vitest（几何/校验 ≥85% 覆盖率）
        静态/类型/快照               ~10%
```

### 6.2 P0 风险与对应测试

| ID | 风险 | 测试策略 | 门禁 |
|---|---|---|---|
| R1 | zoomAt 锚点漂移 | 单测：任意锚点缩放前后映射同一世界点；连锁缩放抵消；边界钳制 | ±0.1px |
| R2 | hit-test 缩放/旋转/分组误判 | 单测：OBB vs AABB、zIndex 遮挡、分组命中 | 全绿 |
| R3 | 导出≠画布 | 集成：pixelmatch + Playwright 截图 diff | <0.5% |
| R4 | schema 非法状态 | 单测：strict/lenient 双模式 + 迁移 fixture | 全绿 |
| R5 | 触控手势冲突 | E2E：`touch-action:none` 断言、pinch 不触发页面缩放 | smoke 绿 |
| R6 | 拖拽重渲染跳变 | E2E：语义化位移断言（相对偏移） | 全绿 |
| R8 | undo/redo 与 schema 不一致 | 单测+集成：手势链回退 | 全绿 |

### 6.3 性能回归门禁

| 指标 | 基线 |
|---|---|
| 画布拖拽帧率 | 桌面 ≥50fps，手机 ≥35fps |
| 拖拽首帧延迟 | <16ms |
| 缩放重渲染（100 元素） | <60ms |
| 导出 PNG（100 元素） | <2s |
| 大画布冷启动（500 元素） | <4s（P2） |

工具：PerformanceObserver(Long Tasks) + fps 采样；**相对回归阈值**（本次 vs 基线劣化率 ≥2σ 告警）而非绝对值硬卡。
CI：GitHub Actions + shard 分片；P0 回归阻断合并。

## 8. 架构决策记录（ADR）

| ADR | 决策 | 理由 |
|---|---|---|
| ADR-001 | 自研画布引擎（非 tldraw/react-flow） | 控制力 + 轻依赖 + 核心纯函数可测 |
| ADR-002 | 客户端导出（非服务端渲染） | 成本第一杠杆；服务端导出成本 ×2–4 |
| ADR-003 | R2 对象存储（零出口费） | 设计师 SaaS 带宽刚需 |
| ADR-004 | html2canvas-pro + IRenderer 抽象 | 保真度瓶颈可替换 |
| ADR-005 | Zustand（非 Redux） | 高频画布更新重渲染控制 |
| ADR-006 | 托管 Postgres（Supabase/Neon，非 K8s） | 免运维，规模前不进 K8s 话题 |
| ADR-007 | stylesFromLayer 画布/导出同一实现 | 强制 DRY，杜绝所见≠所得 |
| ADR-008 | 毛玻璃降级 feature flag + 晨昏双模式 | 低端机性能与 WCAG 对比度风险 |

## 10. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| html2canvas 保真度瓶颈 | 高 | IRenderer 接口 + v1.0 自渲染 canvas |
| 差异化不足 | 高 | AI 原生主线 + 真交付闭环（见 PRD §1.2） |
| 毛玻璃低端机性能/对比度 | 中 | 降级开关 + 晨昏模式 + WCAG 校验 |
| 千级图层性能 | 中 | rbush + 渲染 diff |
| dataURL 文档膨胀 | 中 | objectURL 预览 + 压缩 + v0.2 R2 |
| 服务端导出成本失控 | 中 | 架构强约束：导出客户端优先（ADR-002） |
| 协作复杂度 | 低 | 版本号乐观并发，Yjs 接入点预留 |
